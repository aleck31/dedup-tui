# ADR-0008 开发文档放 .dev/ 并提交进 git

- **状态**: Accepted
- **日期**: 2026-06

## 背景

本项目演化过程中积累了大量“为什么这么做”的权衡。若只存在于对话/脑中，下次维护只能从代码反推，关键理由会丢失。

## 决策

按受众分离文档：

- **`docs/`** — 面向**使用者**的文档（怎么用、装、配置）。
- **`.dev/`** — 面向**开发/维护者**的内部文档（PRD、ADR、设计权衡）。用 `.` 前缀刻意低调（类比 `.github/`），表示“最终用户不关心”，但**随代码提交、版本化**，不 ignore。

ADR 按主题一决策一文件放 `.dev/adr/`，可独立追溯与标记 supersede。

## 影响

- 决策可追溯、随版本演进。
- 用户文档与开发文档职责分离，互不干扰。
- ignore 开发文档等于没沉淀 —— 明确不这么做。
