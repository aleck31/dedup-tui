# ADR-0005 容错：单文件失败不中断整体，apply 后自动复查

- **状态**: Accepted
- **日期**: 2026-06

## 背景

在 109G 真实测试用例上首次 `--apply` 时连续暴露三个会损坏数据/状态的问题。

## 决策

- `apply_decisions` 对每个文件独立 try/except，返回 `(removed, skipped, failed)`，单个失败记录并继续。
- `quarantine()` 在 move 失败时回滚隔离区半成品副本（含清除 immutable 标志），保证文件不会“原地 + 隔离区各一份”。
- apply 后自动重新扫描，报告残留重复组数（`--no-recheck` 可关闭）。

## 踩坑记录（真实测试逼出的三个 bug）

1. 一个 macOS `uchg` 锁定文件让整个 apply **抛异常中断**，留下半完成状态 → 每文件容错。
2. `shutil.move` 跨卷 = copy+unlink，unlink 失败导致文件**原地和隔离区各一份**（脏状态）→ 失败时回滚副本。
3. apply 后**无法确认是否清干净**，要手动再扫 → 自动复查。

三个都是 dry-run / headless 单测发现不了的，只有真实数据端到端跑才暴露。

## 影响

**核心教训**：删除类工具不在真实用例上跑完整周期，就不算做完。
