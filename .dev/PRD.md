# PRD — dedup-tui (Duplicate Finder)

## 问题

磁盘里散落大量重复文件（同一内容存在于多个目录/多个文件名下），占用空间且难以人工梳理。需要一个工具：找出重复、让人决定每组保留哪个、安全地移除其余。

起源是一次真实磁盘清理：`/Users/Shared/Workspaces`（109G、46850 文件）里有 7533 组重复（约 1G）。这个数据集后来固定为工具的验收测试用例——**工具必须能把它完整、可信地处理完**。

## 目标用户

开发者 / 技术用户，命令行环境，偶尔做磁盘大扫除。不面向非技术用户，不做 GUI。

## 核心需求

1. **找重复**：基于内容（哈希），与文件名/时间无关。
2. **人工审查**：逐组查看副本，决定保留哪个/哪些。默认选最原始的副本。
3. **多保留**：一组里允许保留多个副本（同内容要放在不同位置的场景），但至少保留 1 个。
4. **安全移除**：删除可恢复、可验证，绝不在出错时损坏数据。
5. **跨平台**：macOS / Linux / Windows 都能跑。
6. **可分发**：`uvx` / `pipx` 一条命令安装运行。

## 非目标（明确不做）

- **不做自动规则决策**：不内置“按路径深度/副本目录名自动选 keeper”的规则引擎。去重决策的歧义性高，自动规则容易误删；保持“人工审查为主、默认选最原始”。（注：这是已知的体验上限——7533 组仍需人逐组过，工具无法消除这个决策成本，只能让它顺畅。）
- **不做相似文件检测**：只做字节级完全相同的重复，不做“相似图片/近似内容”的模糊匹配（那是 rmlint/Czkawka 的 `-D` 之外的特性，超出范围）。
- **不做 GUI**：纯 TUI。
- **不替用户判断价值**：工具只处理“重复”，不判断文件本身是否该留（资料取舍是用户的事）。

## 验收标准

在 109G 真实测试用例上 `--auto --apply` 端到端跑通：
- 移除数 = 树中减少数 = 隔离区增加数（账目平）。
- 保留的副本完好，被移除的可从隔离区恢复。
- 单个文件失败（如锁定文件）不中断整体，记录并跳过。
- 完成后自动复查，报告残留重复数。

## 已知现实

- 对多数真实磁盘，重复占比很小（测试用例 109G 仅 ~1G 重复）。去重不是省空间的主力手段，真正的空间在“资料取舍”与系统 swap。工具价值在“偶尔需要时能可信地用”，不是高频工具。
